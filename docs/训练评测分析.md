## 3. 时间效率：训练让模型"越修越快"

| | epoch 1 | epoch 5 | 变化 |
|---|--------|--------|------|
| rollout 生成 | 30.8 min/步 | 21.2 min/步 | **-31%** |
| 训练更新 | 11.4 min/步 | 6.6 min/步 | **-43%** |
| 单步总时长 | 46.7 min | 30.8 min | **-34%** |
| 平均轮数/会话 | 17.6 | 9.0 | **-49%** |
| 每 epoch token | 303 万 | 174 万 | **-43%** |

原因：模型越训越会"直击要害"——修同一 bug 的轮数减半 → 生成 token 减少 →
gen 和 update 都快。**这是训练有效的强证据（行为层面）。**

## 5. 关键发现：训练 gateway 双解析压低 rollout 成功率

- **现象**：同一批 32 样本，训练 step 1 per-session 通过率 29%，干净评测通过率 81%
- **根因**：verl rollout 的 vLLM 只生成原始文本（不解析工具调用），Gateway codec
  `_process_tool_calls_vllm` 用 hermes 解析器**二次解析** `<tool_call>JSON</tool_call>`；
  Qwen3-8B 输出的 JSON 偶尔格式瑕疵 → `json.loads` 抛 `JSONDecodeError` →
  该回合请求失败 → agent 白费轮次/失败
- **量化**：26 步共 **1,601 个解析错误事件**（占 30,235 次模型调用的 5.3%）；
  平均 9 回合的会话约 **38% 至少中一次**
- **影响**：per-session 通过率被压到 29~59%（真实 ~80%）；训练指标曲线被系统性
  低估；数据效率低 + 梯度信号被噪声稀释
- **修复方案（TODO §C 6.5 最高优先）**：A. gateway codec 容错（JSON 修复重试 +
  合成错误提示让 agent 重试）；B. 训练 rollout 的 vLLM 直接启用
  `--enable-auto-tool-choice --tool-call-parser hermes`（与评测统一，消除双解析）
- **验收**：修复后同配置小样本重跑，per-session 通过率应回到 80%+
- **✅ 方案 A 已实现并上机验证（2026-08-09，v0.31.8 / 服务器 commit `5cc88ec`）**：
  train3 × 1 epoch（12 会话）3 个 step 全部 4/4 会话成功，15 次 JSONDecodeError
  全部 repair 救回（0 次 unrecoverable / synthetic retry）；通过率 0→0.25→0.75 与
  gateway 修复前基线一致——**修复不改模型行为，只消除解析错误导致的会话失败**

## 6. 结论

1. **训练真实有效**：行为（轮数 -49%）与评测（+6.8pp）双证据
2. **训练曲线被低估**：真实起点 ~76%（评测），29% 是 gateway 解析损耗；
   曲线 0.29→0.74 中一部分是"从解析故障恢复"
3. **修复 gateway 解析的预期收益**：per-session 通过率 59% → 80%+，
   同样成本下梯度更强、训练更快
