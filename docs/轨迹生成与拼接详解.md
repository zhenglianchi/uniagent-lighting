## 1. 核心数据结构（先记这些）

**`TrajectoryBuffer`（session.py:36）——一条轨迹的 token 级缓冲**：
```python
class TrajectoryBuffer:
    prompt_ids: list[int]          # 输入 token（首轮编码后固定）
    response_ids: list[int]        # 输出 token（每轮生成/工具结果增量 append）
    response_mask: list[int]       # 1=模型生成，0=工具结果（loss 只算 1）
    response_logprobs: list[float] # 生成 token 的 logprob（工具结果位置为 0.0）
    generation_versions: list      # [(min_global_steps, max_global_steps)] 每轮一次
    routed_experts: Any | None     # MoE 路由（本任务无）
```

**`ChainState`（session.py:79）——一条“链”**：`chain_id`、`message_history`、
`message_tip_hash`、`active_tool_schemas`、`buffer`（上面的 TrajectoryBuffer）、
`last_assistant_start`（回滚锚点）、`updated_seq`。

**`MaterializedChain`（session.py:94）**：物化后的链 = `trajectory` + `order_seq`。

**`EncodedData`（session.py:102）**：`_prepare_generation_inputs` 的产物——本轮
的 `buffer`（含增量）、`context_ids`、`sampling_params`、`messages`、`tools`、
`chain_id`、`capacity_exhausted`、`last_assistant_start` 等。

**`Trajectory`（gateway/session/types.py:45）**：最终物化结果——`prompt_ids /
response_ids / response_mask / response_logprobs / reward_info / num_turns /
extra_fields（min/max_global_steps、materialization_reason）`。

## 3. 第二步：_prepare_generation_inputs（编码 + 选链 + 增量拼接）

**位置**：`gateway/session/session.py:386`。这是“拼接”发生的地方，分三种情况：

### 3.1 首次请求（新链）：全量编码
```python

    chain_id = None

```
**处理**：本任务首轮 `prompt_ids` = 1288 token（题目 + system 提示 + 工具 schema 编码后）。

### 3.2 续链（agent 下一轮）：选链 + 增量编码 + 拼接
```python
# session.py:412-438（节选）
selected_chain, rollback_to_last_assistant = selection
buffer = self._copy_trajectory_buffer(selected_chain.buffer)   # 复制上轮 buffer（快照）
...

incremental_ids = self._codec.encode_incremental(incremental_messages, ...)  # 增量编码
buffer.response_ids.extend(incremental_ids)                   # ★ 拼接到 response_ids
buffer.response_mask.extend([0] * len(incremental_ids))       # ★ 工具结果 mask=0
```

**处理**：工具结果作为 user 消息增量编码，**拼到 buffer 尾部且 mask=0**（不参与
loss）。本任务第 1 次工具结果 = `cat solution.py` 的 253 token。

### 3.3 回滚（可选处理）：last_assistant_start 截断
```python

    del buffer.response_ids[last_assistant_start.response_ids_len:]
```

**处理**：agent 重发同一前缀的请求时，把上一轮未提交的 assistant 生成截掉重来

### 3.4 容量检查 + max_tokens 裁剪

**处理**：单条轨迹接近上限时裁剪本轮 `max_tokens`；超限则走分链（§6）。本任务
1288+1004=2292 < 上限，未触发。

## 6. 第五步：_commit_generation_to_chain（拼接核心）

**位置**：`session.py:670`。
```python
def _commit_generation_to_chain(self, encoded, assistant_msg):
    message_history = list(encoded.messages) + [assistant_msg]
    message_prefix_hashes = self._extend_message_prefix_hashes(
        encoded.incoming_message_prefix_hashes, [assistant_msg])
    if encoded.chain_id is None:
        # 新链：创建 ChainState，buffer = encoded.buffer（含本轮生成）
        self.active_chains.append(ChainState(chain_id=..., buffer=encoded.buffer, ...))
    else:
        # 续链：更新已有 ChainState（buffer 已含增量）
        self.active_chains[chain_index] = ChainState(chain_id=previous.chain_id,
            buffer=encoded.buffer, ...)
```

**关键**：模型生成 token 在哪一步进 buffer？看 `run_generation` 的中间段
（session.py:272-297）：
```python
encoded.buffer.response_ids.extend(response_ids)          # ★ 模型 token 拼入
encoded.buffer.response_mask.extend([1] * len(response_ids))  # ★ mask=1
if sampling_params.get("logprobs", False):
    log_probs = list(output.log_probs)
    encoded.buffer.response_logprobs.extend(log_probs)
    self._assert_response_logprob_alignment(encoded.buffer)   # 长度对齐校验
```

**所以“拼接”是双向的**：
- 模型生成 → `response_ids` 尾部 + `mask=1` + logprobs（§6）；
- 工具结果（下一轮 user 增量）→ `response_ids` 尾部 + `mask=0`（§3.2）。

## 8. finalize：链 → Trajectory（物化）

**调用链**：`framework.py:700` → `gateway.py:269` → `session.py:339`。
```python
# session.py:339  finalize
async def finalize(self) -> list[Trajectory]:
    self._materialize_active_chains()      # :759 把剩余 active 链也物化
    self.phase = SessionPhase.FINALIZED
    ordered = sorted(self.materialized_chains, key=lambda c: c.order_seq)
```

**`_build_materialized_trajectory`（session.py:770）——Trajectory 组装**：
```python
response_logprobs = list(chain.buffer.response_logprobs) if chain.buffer.response_logprobs else None
```

## 11. 本任务实例：轨迹一步步拼接全过程

**初始**：`prompt_ids=[1288]`，`response_ids=[]`，`mask=[]`，`logprobs=[]`。

| 轮 | 事件 | response_ids 增量 | mask 增量 | 累计 response | 累计 mask 分布 |
|---|---|---|---|---|---|
| 1 | 模型生成（读文件调用） | +26 | 1×26 | 26 | 26×1 |
| 2 | 工具结果（cat solution.py） | +253 | 0×253 | 279 | 26×1 + 253×0 |
| 3 | 模型生成（heredoc 修复） | +320 | 1×320 | 599 | 26×1+253×0+320×1 |
| 4 | 工具结果（heredoc 回显） | +30 | 0×30 | 629 | …+30×0 |
| 5 | 模型生成（自测命令） | +35 | 1×35 | 664 | …+35×1 |
| 6 | 工具结果（自测输出） | +310 | 0×310 | 974 | …+310×0 |
| 7 | 模型生成（提交命令） | +30 | 1×30 | **1004** | **411×1 + 593×0** |

**最终 Trajectory**：`prompt_ids=1288`、`response_ids=1004`、`mask` 411×1+593×0、

## 13. 一句话总结

**轨迹 = 每轮“模型生成（mask=1 + logprob）”与“工具结果（mask=0）”交替 append 进
链的 TrajectoryBuffer，finalize 时物化成 Trajectory，再经 framework 拼成
prompts/responses/input_ids/loss_mask 写进 TQ**——Gateway 是唯一的轨迹来源，
runner 全程不碰轨迹。
