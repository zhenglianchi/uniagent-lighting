# 数据流与 Gateway 源码导读

> 学习入口：从一条 agent 会话开始，看它如何变成 verl 的训练样本。重点在
> **uni-agent 的 Gateway 如何物化轨迹、如何进入训练**。

## 1. 端到端数据流（学习主线）

```
① Agent 决策循环                    ② Gateway 会话（uni-agent）
   mini-swe-agent / Claude Code        session.py: 链(chain)管理、轨迹缓冲
   └─ 每轮调模型(OpenAI/Anthropic)  ─▶  └─ prepare: 编码上下文、容量检查
                                         └─ generate: 调 vLLM、append response
                                         └─ finalize: 物化链 → Trajectory 列表
                                                    │
③ 框架层（uni-agent）               ④ 数据平面（TransferQueue）
   framework.py                         TQ KV store
   └─ _trajectory_to_tq_field_and_tag ─▶  └─ kv_batch_put（prompts/responses/
   └─ _write_session_trajectories_to_tq     logprobs/masks/rm_scores/num_turns）
                                                    │
⑤ 训练（verl）                     ⑥ 权重 → 服务
   trainer_base.py: kv_batch_get ─▶ GRPO(LoRA) ─▶ checkpoint ─▶ merge ─▶ vLLM
   padding_utils: batch 补全
   replay_buffer: off-policy 过滤
```

## 2. Gateway 源码定位（重点）

所有路径基于仓库 `vendor/uni-agent/uni_agent/`。

### 2.1 会话与链（session.py）——轨迹的诞生地

| 函数 | 作用 |
|---|---|
`session.py::run_generation` | 每轮生成入口：prepare → 调模型 → commit 到链 |
`_prepare_generation_inputs` | 编码消息、选链、**容量检查**（`max_trajectory_length`） |
`_select_chain` | 通过消息 hash 匹配已有链（续链/回滚） |
`_commit_generation_to_chain` | 生成结果 append 到链的 buffer（response_ids/mask/logprobs） |
`_close_length_exhausted_chain` | 长度耗尽时物化链（→ 空轨迹的产生点） |
`finalize` | 会话结束：物化所有链 → 返回 Trajectory 列表 |

**关键数据结构**：`TrajectoryBuffer`（prompt_ids / response_ids / response_mask /
response_logprobs / generation_versions）——一条轨迹的 token 级内容全在这里。

### 2.2 轨迹转训练样本（framework.py）——轨迹如何变成 verl batch

| 函数 | 作用 |
|---|---|
`_trajectory_to_tq_field_and_tag` | Trajectory → TQ 字段（**重点**：字段如何组装） |
`_write_session_trajectories_to_tq` | 写入 TQ（含**空响应轨迹跳过**补丁） |

**产出的字段**（verl 训练直接消费）：

| 字段 | 含义 |
|---|---|
`prompts` / `responses` | 输入输出 token ids（tensor） |
`input_ids` / `attention_mask` / `position_ids` | 拼接后完整序列 |
`response_mask` / `loss_mask` | 哪些 token 参与 loss（工具结果 = 0） |
`rollout_log_probs` | 生成时 logprob（GRPO 需要） |
`rm_scores` | reward（最后一位置 reward_score） |
`num_turns` | 轮次（int64 tensor，8B 修复点） |
`global_steps` / `min/max_global_steps` | 权重版本跨度（off-policy 判定） |

### 2.3 训练侧消费（verl）

| 文件 | 作用 |
|---|---|
`verl/trainer/ppo/v1/trainer_base.py` | `kv_batch_get` 读 batch、`upsample_batch_to_divisible_size` 补 padding |
`verl/trainer/ppo/padding_utils.py` | padding 行构造（`num_turns=0` Python int → 13B bug 点） |
`verl/trainer/ppo/v1/replay_buffer.py` | off-policy 过滤（`max_off_policy_threshold=8 / drop`） |
`verl/workers/rollout/vllm_rollout/vllm_async_server.py` | rollout 引擎（EAGLE-3 投机、logprobs 修复） |

## 3. 轨迹文件格式（分析用）

训练轨迹（解压 `work/logs/humanevalfix_full_20260809/humanevalfix_trajectories.tgz`
后，`humanevalfix/` 下的会话目录）每个会话目录：

| 文件 | 内容 |
|---|---|
`framework.log` | 会话摘要：轮次 / prompt/response tokens / **reward_score** / 是否截断 |
| `task.log` | agent 每步动作（LiteLLM 调用、工具执行、测试结果） |
| `trajectory.json` | 可读摘要：num_turns、prompt_len、response_len、reward_info |
| `trajectory.npz` | token 级数据：prompt_ids / response_ids / response_mask / logprobs |

示例（humanevalfix_full step_1 某会话）：
```
framework.log: [0] turns=6 prompt_tokens=1273 response_tokens=967 reward_score=0.0
trajectory.npz: traj0_prompt_ids(1273,) traj0_response_ids(967,) traj0_response_mask(967,) traj0_response_logprobs(967,)
```

> 注意：双机（dual_async）训练时 token 级轨迹经 TQ 实时传输，会话目录只落
> `task.log`；白盒/黑盒 full 有完整 `trajectory.json/npz`，是分析轨迹的首选。

## 4. 建议学习顺序

1. `docs/architecture.md` —— 平台化分层（10 分钟）
2. **本文 §1 数据流图** —— 全链路心智模型（10 分钟）
3. `session.py`：`run_generation` → `_commit_generation_to_chain` →
   `finalize` —— Gateway 如何攒出一条轨迹（30 分钟）
4. `framework.py`：`_trajectory_to_tq_field_and_tag` —— 轨迹如何变训练样本
   （20 分钟）
5. `trainer_base.py` + `padding_utils.py` —— verl 如何消费（20 分钟）
6. 实战：`scripts/analyze_trajectory.py` 分析一条真实轨迹（15 分钟）
