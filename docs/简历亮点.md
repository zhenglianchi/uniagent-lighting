# 简历亮点

## 项目简介

基于 verl/uni-agent 构建代码智能体训推平台：白盒（mini-swe-agent）与黑盒
（Claude Code）双 harness 接入，用户侧 agent 经云端 Gateway 采集 token 级轨迹、
腾讯云沙箱负责执行，云端完成 GRPO（LoRA）训练并自动产出可服务权重。以
HumanEvalFix 全样本训练为基准完成三条训练路径（白盒 83.2% / 投机 82.61% /
黑盒 80.75% / 双机全异步 83.23% 通过率），并完成 rollout 侧系统化性能优化、
双机全异步 + Mooncake 数据平面与平台化架构落地。

## 亮点一：Agent RL 训练链路从零打通与源码级排障

从零搭建 verl 0.9 全链路（vLLM 引擎、Gateway 会话、TransferQueue、LoRA GRPO），
解决版本兼容矩阵（torch 2.9 / vllm 0.11.1 / transformers 4.57 等）与部署问题，
编写 8 个幂等补丁。定位并修复 3 个上游 RL 正确性 bug：

- **LoRA merge 梯度未生效（verl#7014）**：merge 分支返回 live 存储别名，导致
  rollout 每步同步的是未带 LoRA 的基座权重，训练梯度从未作用到生成；backport
  修复并验证策略收敛恢复
- **EAGLE-3 logprobs 全丢（vllm#30059）**：投机解码下 logprobs=0 返回空，导致
  训练无梯度信号；定位并修复（0→1）
- **Gateway 工具解析错误杀会话**：5.3% 的 hermes 解析失败率导致约 38% 会话
  受影响；实现 JSON 修复重试 + 合成重试提示，解析错误不再杀会话

## 亮点二：Rollout 生成优化（投机解码 + LoRA 引擎热插）

针对 Agent RL 的生成瓶颈（SWE-bench/HumanEvalFix 长 prompt 多轮场景）做系统化
优化与 A/B 验证：

- **EAGLE-3 投机解码**：生成吞吐 **+41.7%**（199→282 tok/s），单 token 延迟
  -39.5%；25 步全样本训练验证训练质量无损（评测与基线持平）
- **LoRA + vLLM 引擎常驻（adapter 热插）**：每步权重同步 2.5s（仅 ~100MB
  adapter）vs 全参 15GB refit，将训练-推理切换从分钟级降到秒级
- **A/B 方法论**：同配置 spec on/off 对照，step 时长 / 吞吐 / 通过率 / 评测
  四维对比，排除优化与修复收益混杂

## 亮点三：黑盒（Claude Code）训练接入与行为量化分析

打通 Anthropic 协议黑盒训练链路（Claude Code 编排 + Qwen3-8B 推理），并完成
系统性行为分析：

- **排障链**：从 5 轮故障中定位根因（沙箱生命周期、隧道转发目标、max_tokens
  超 vLLM 容量、客户端 usage 误判、MCP 框架版本兼容），每条均有源码/日志定位
- **行为对比**：黑盒起点通过率 0.57 vs 白盒 0.29（Claude Code 编排初始更强）；
  轮数翻倍（24 vs 11）、响应更长（3158 vs 1665）、吞吐低 35%；定位长上下文
  prefill 平方级成本与 prefix cache 命中瓶颈
- **成果**：全样本 25 步训练完成，最终通过率 **80.75%**（vs 基座 76.4%，
  +4.35pp）

## 亮点四：平台化训推架构（agent 与执行环境分离）

实现"用户侧 agent + 云端 Gateway + 沙箱执行"三层解耦，符合 on-policy 约束
（token-truth 轨迹由 Gateway 云侧物化）：

- **外部 agent runner**：建沙箱 → 暴露任务（session URL/instance_id）→ 等待
  外部 agent → 云侧 reward 的完整协议
- **MCP 工具转发层**：手写 stdio JSON-RPC MCP server（`sandbox_mcp_server.py`），
  将 Claude Code 的 Bash/Read/Write/Edit 转发到云端沙箱执行，解决黑盒 harness
  无远程执行抽象的工程难题
- **验证**：白盒两个既有权重完成单步闭环（reward 1.0、轨迹结构正确、权重未
  覆盖）；黑盒完整训练（25 步）与评估结果计为平台化训练产出

## 亮点五：双机全异步 + Mooncake 训练（完成，83.23%）

基于 verl v1 `separate_async`（trainer 与独立 rollout 引擎分卡并行）+
TransferQueue MooncakeStore 数据平面 + EAGLE-3 投机，完成双机全样本正式训练：

- **加速实测**：每步墙钟 -39%（sync 79.4s → separate_async 48.1s，3 步均值），
  采样与训练完全重叠（off-policy 实际落后 2~4 轮 < 阈值 8）
- **训练质量无损**：25 步 0 硬错误，评测 **83.23%**（134/161），与单机白盒
  baseline 83.2% 持平并略高，验证全异步 + Mooncake + 投机组合的端到端可用性
- **Mooncake 链路源码级排障**：定位并修复 `num_turns` 13B 写读类型不一致
  （verl padding 行 Python int vs int64）、空响应轨迹 0 字节 slice 被 master
  拒绝、checkpoint 磁盘累积（`max_actor_ckpt_to_keep` 传递 + 守护进程兜底）
- **平台化表述**：双机形态同样以平台化链路（agent → 云端 Gateway → 轨迹 →
  训练）产出，成果计为平台化训练结果
