### 6.1 路由与协议转换

### 6.2 run_generation 内部分解（session.py:220）

```python
async with self.request_lock:
    encoded = await self._prepare_generation_inputs(request)   # ① 编码 + 选链 + 容量检查
    if encoded.capacity_exhausted: ...                          # ② 分链物化（本任务未触发）
output = await backend.generate(                               # ③ vLLM 生成（锁外）
    request_id=..., prompt_ids=encoded.context_ids,
    sampling_params=encoded.sampling_params, ...)
assistant_msg, finish_reason = await self._codec.decode_response(  # ④ 解码
    response_ids, tools=encoded.tools, stop_reason=output.stop_reason)
self._commit_generation_to_chain(encoded, assistant_msg)         # ⑤ 写链
```

- **① `_prepare_generation_inputs`（386）**：`codec.encode_full`（codec.py:272，
  完整消息+system prompt）或 `encode_incremental`（315，复用 system 前缀）→
  `context_ids`；同时 `_select_chain`（526，按消息 hash 匹配已有链）。
- **③ `backend.generate`**：backend 就是 verl 侧 vLLM 引擎的
  `LLMServerClient`——返回 `token_ids + log_probs + stop_reason`（本任务 26/320/35/30
  四段）。`_assert_response_logprob_alignment`（639）校验 logprob 与 token 对齐。
- **④ `decode_response`（codec.py:355）**：token → assistant 消息 / 工具调用
  （vllm/sglang 解析、JSON 修复重试）。
- **⑤ `_commit_generation_to_chain`（670）**：把 prompt/response/mask/logprobs
  append 进当前链的 `TrajectoryBuffer`——**这就是 token 级轨迹的累积点**。

### 6.3 链机制（为什么叫“链”）

- 一个 session 可以有多个链（chain）：多轮消息 hash 匹配续链（`_select_chain`，
  526），可回滚；
- 容量检查：`_prepare_generation_inputs` 里 `current + incremental >=
  max_trajectory_length` → `capacity_exhausted` → `_close_length_exhausted_chain`
  （712）物化冻结 → 开新链（本任务 1288+1004 < 上限，单链未触发）；
- `finalize`（339）→ `_materialize_active_chains`（759）把每个链物化成一条
  `Trajectory`，按 `order_seq` 排序返回。

### 6.4 codec（翻译官，不调模型）

| 方法 | 作用 |
|---|---|
| `encode_full`（272） | 完整消息列表 → input token ids |
| `encode_incremental`（315） | 增量消息（复用 system prompt 前缀） |
| `decode_response`（355） | 模型 token → assistant 消息/工具调用 |

模型调用在 `backend.generate`（session.py:255），codec 只在前后做格式转换。
