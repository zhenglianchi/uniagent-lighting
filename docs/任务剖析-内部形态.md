## 3.5 task 数据从哪来、怎么下发（数据源 + 双通道）

### 3.5.1 数据源：task.jsonl 什么时候生成、谁读

1. **离线生成**：`scripts/data/make_humanevalfix_data.py` 从 HumanEvalFix 数据集
   构建 `work/data/humanevalfix_train161.jsonl` / `humanevalfix_val.jsonl`
   （每条记录 = §2.1 的完整 JSON，含 prompt / tools_kwargs / reward_model）；
2. **训练启动时加载**：`trainer_base.py:545 _init_dataloader` →
   `create_rl_dataset(config.data.train_files, ...)`（读 jsonl，转 RL 数据集）→
   `StatefulDataLoader`（564 行）；
3. **每个 step 消费一条 batch**：`trainer_base.py:1131 _add_batch_to_generate`：
   `next(self.train_dataloader_it)` → batch_dict（含 raw_prompt / tools_kwargs /
   data_source / reward_model）。**sample 20 的 jsonl 记录就是在这里进入内存的**。

### 3.5.2 下发双通道（内部形态没有 task.json 文件）

`_add_batch_to_generate`（trainer_base.py:1131-1150）一次性做两件事：

```python
# 通道 A：把 prompt 注册进 TQ（tag-only，供 ReplayBuffer 状态机跟踪）
tags = [{"is_prompt": True, "status": "pending", "global_steps": self.global_steps}] * len(batch)
tq.kv_batch_put(keys=list(batch["uid"]), partition_id="train", tags=tags)

# 通道 B：整个 batch 以内存参数交给 agent 框架
self.agent_loop_manager.generate_sequences(batch)
```

| 通道 | 内容 | 流向 | 用途 |
|---|---|---|---|
| A | `uid` + tag（pending/running/finished/failure） | TQ | ReplayBuffer 判断该组是否完成、staleness 排序 |
| B | batch（raw_prompt / tools_kwargs / uid / global_steps） | `generate_sequences` → framework → `_run_session` → runner 函数参数 | **真正的 task 内容** |

**读取点**：runner 从函数参数拿 task——`mini_swe_agent_runner.py:570`
`extract_task(raw_prompt, tools_kwargs)` 解析出 `instance_id` / `fail_to_pass` /
`env.files`。所以内部形态**没有 task.json 文件**，task 内容全程在内存里流动。

### 6.5.2 核心数据结构（先记这些）

**`TrajectoryBuffer`（session.py:36）——一条轨迹的 token 级缓冲**：
```python
class TrajectoryBuffer:
    prompt_ids: list[int]          # 输入 token（首轮编码后固定）
    response_ids: list[int]        # 输出 token（每轮生成/工具结果增量 append）
    response_mask: list[int]       # 1=模型生成，0=工具结果（loss 只算 1）
    response_logprobs: list[float] # 生成 token 的 logprob（工具结果位置为 0.0）
    generation_versions: list      # [(min_global_steps, max_global_steps)] 每轮一次
    routed_experts: Any | None     # MoE 路由（本任务无）
```

**`ChainState`（session.py:79）——一条“链”**：`chain_id`、`message_history`、
`message_tip_hash`、`active_tool_schemas`、`buffer`（上面的 TrajectoryBuffer）、
`last_assistant_start`（回滚锚点）、`updated_seq`。

**`MaterializedChain`（session.py:94）**：物化后的链 = `trajectory` + `order_seq`。

**`EncodedData`（session.py:102）**：`_prepare_generation_inputs` 的产物——本轮
的 `buffer`（含增量）、`context_ids`、`sampling_params`、`messages`、`tools`、
`chain_id`、`capacity_exhausted`、`last_assistant_start` 等。

**`Trajectory`（gateway/session/types.py:45）**：最终物化结果——`prompt_ids /
response_ids / response_mask / response_logprobs / reward_info / num_turns /
extra_fields（min/max_global_steps、materialization_reason）`。

```python

    message_prefix_hashes = self._extend_message_prefix_hashes(
        encoded.incoming_message_prefix_hashes, [assistant_msg])
    if encoded.chain_id is None:

        self.active_chains.append(ChainState(chain_id=..., buffer=encoded.buffer, ...))
    else:
        # 续链：更新已有 ChainState（buffer 已含增量）
        self.active_chains[chain_index] = ChainState(chain_id=previous.chain_id,
            buffer=encoded.buffer, ...)
```

**关键**：模型生成 token 进 buffer 的代码在 `run_generation` 中间段

### 6.5.14 一句话总结

**轨迹 = 每轮“模型生成（mask=1 + logprob）”与“工具结果（mask=0）”交替 append 进
链的 TrajectoryBuffer，finalize 时物化成 Trajectory，再经 framework 拼成
prompts/responses/input_ids/loss_mask 写进 TQ**——Gateway 是唯一的轨迹来源，
runner 全程不碰轨迹。
